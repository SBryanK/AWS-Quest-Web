# Continuing, updating, and reconciling a study site

Reopen the actual site/source and inspect its saved revision. Resume unfinished work before inventing a replacement. Inventory existing lessons, source pages, map nodes, questions, glossary, diagrams, public assets, notes/progress keys, and deployment audience.

Create a change ledger with source edition/page, old assertion, new assertion, primary evidence, affected lesson/question/map IDs, and resolution. Fix a changed fact in every dependent learning surface. Preserve historical source wording as context when useful and label current corrections. Mark unresolved discrepancies and ask only if they block a material decision.

Keep IDs stable. For merges/splits, add explicit mappings and preserve orphaned notes in an archive visible to the user. Back up before migrating substantial user data; validate new data and allow rollback. Do not clear localStorage because a layout or schema changed. Validate old backups as well as new ones when compatibility is promised.

Keep coverage accurate after adding/removing sources. Check broken links, stale counts, question rationales, language consistency, and testable calculations. If styling changes only, do not rewrite teaching content. Publish the reviewed source state and retain public/private access unless the user changes it.
