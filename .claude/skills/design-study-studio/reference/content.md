# Content, learning, and data

Use a table for exact comparisons, a mind map for categories, a flow for a process, a diagram for topology, and a simulator when changing a parameter reveals a mechanism. Do not create a chart merely to fill space.

A mind map should have a readable overview and a focused branch/list. Include search, explicit selected category, keyboard navigation, and a narrow-screen equivalent. Do not cram hundreds of labels into one viewport. Reveal details on demand. A recall mode must actually hide answers and explain that category/context clues may remain.

For learning, separate read, attempted, self-rated recall, and demonstrated practice. XP is motivation, not mastery or an exam prediction. Place examples, counterexamples, and feedback near the concept. Retain source-page links and distinguish source content from new explanation/current correction. Preserve the learner's notes and difficulty ratings.

Charts require meaningful units, labels, data provenance, and an accessible text/table equivalent when appropriate. Hand-authored SVG works for small precise diagrams; a maintained local library is acceptable for complex charts. Use a group structure for interactive charts so marks remain accessible; `role=img` is suited to static graphics. Use native controls/links or fully implement keyboard behavior. A band must be labeled according to its actual meaning (prediction, confidence, quantiles, scenario range); never call all ranges confidence intervals.

Prefer honest axes, comparisons, and limitations. Do not derive decorative shapes that imply measurements the source does not contain. Never fabricate a successful user action, calculation, test, or learning score. Print only the intended selection; disclose whether export includes answers.
