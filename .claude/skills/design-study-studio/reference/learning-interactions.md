# Learning interactions

## Plan
Map prerequisites and weight dense concepts more heavily. Size work to the user's daily time. A default 7-day learning route plus revision days is only appropriate when the brief supports it. Distinguish estimated reading time from practice/retrieval time. Reserve time for weak areas and fresh application. Never promise mastery from completing pages.

## Recall and practice
Show the prompt before the answer. Let the user explain aloud or type privately, then reveal reasoning and rate difficulty. Use spaced revisits and wrong-answer queues; a heuristic schedule is acceptable when identified as a heuristic. Do not count clicking reveal or self-rating as an objectively correct answer.

Use original scenarios. Every multiple-choice option gets a rationale. Multi-answer scoring must compare exact sets, reject missing/extra selections, and handle duplicate input safely. Show the requested selection count. Give feedback without punishment, shame, or unearned celebration. Retrying a question must not inflate mastery.

## Maps and cheat sheets
Group items by the question they answer: identity, storage, argument type, process stage, statistical goal, etc. Each leaf has name, expansion, short function, choose-when constraint, memory hook, closest confusion, and lesson/source link. Match the catalog to the supplied material and declare scope; do not claim every AWS product or every theory in a field.

Use overview → category → subgroup → concept. Provide search and a readable categorized list for narrow screens. Recall mode hides answer names, and exposes them only after an intentional reveal. A category hint is acceptable if the learner knows it remains. Provide printable selections where useful.

## Simulations
Only build a lab when a parameter change teaches causality or a tradeoff. Publish assumptions and units. Use deterministic logic and representative edge cases. Diagrams that show branching, feedback or topology should be exact vectors/code, not generated pictures with invented labels.

## Progress
Keep lesson IDs stable. Distinguish read, practiced, self-rated explainable, and due for review. Preserve notes during navigation, UI settings, errors, and updates. If using localStorage, say that progress is device/browser-specific. Export/import should use a versioned schema and validate values before changing saved state. Do not simulate account sync.
